# 使用说明 — 视频下载工具箱

> 一句话：双击 `启动工具箱.bat`，**直接打开主界面**（原生应用窗口），
> 全部模块在界面里点按钮统一管理；桥接服务自动启动。
> 2026-11-07 起根目录只有这一个启动器，旧的 `.vbs` 壳、终端菜单与单工具 `.bat` 已全部退役。

## 0. 首次使用（30 秒）

1. 双击 `启动工具箱.bat`（项目根目录 `E:\lp\lp\douzy\`）。
   黑框一闪而过属正常（`.bat` 固有），它启动完两个东西就自己关闭。
2. 弹出「视频下载工具箱」主界面窗口（原生应用窗口，浏览器内核无地址栏）——
   桥接服务 127.0.0.1:8518 已被自动拉起，全部模块在这里点按钮使用。
3. 不需要安装任何东西；如需下载视频，确保网络可访问对应平台。

> **为什么双击后没有菜单了？** 菜单已退役：主界面本身就是统一管理入口。
> 高级用法：`启动工具箱.bat bridge`（前台桥接调试）。
> 启动器文件必须 GBK + CRLF 编码、行首 `chcp` 之后不得再有中文 ——
> UTF-8 文件加中途代码页切换会让 cmd 解析错位（中文行被劈开当命令执行，实测踩过）。

## 0.5 关于终端（黑）窗口

双击时的黑框是 `.bat` 固有的，一闪而过。此后图形界面内部**不会**弹终端：
子进程统一以隐藏窗口方式拉起，输出全部送进界面下方的日志窗格。只有这几处例外：

| 入口 | 会不会有终端 | 说明 |
|---|---|---|
| 双击 `启动工具箱.bat` | 闪一下 | 启动完自动关闭；主界面窗口常驻 |
| `启动工具箱.bat bridge` | 有（前台） | 桥接调试用，关窗口即停 |
| 工具界面里点任意按钮 | **无** | 子进程用 `CREATE_NO_WINDOW` 启动，输出进日志窗格 |

### 抖音下载器为什么改成用「输入框」收链接

它原本靠终端里的 `input()` 循环收链接。工具箱改成无窗口启动后，子进程没有控制台，
`input()` 会立刻 EOF，链接就没地方输入了。
好在 `launcher.py` 本来就支持把链接当命令行参数传，所以工具箱改成
**先在界面输入框里收文本，再带参数无窗口启动**——链接照样能一次粘多个，
还顺带修掉了以前「提示显示在日志窗格、输入却要切到黑窗口」的割裂感。

> **一处副作用**：抖音的**交互式重新登录**需要终端
> （`login_flow.can_interactive_login()` 会检查 `sys.stdin.isatty()`）。
> 该检查在无控制台时安全返回 False，程序改为在日志里提示需要重新登录，**不会崩溃**。
> 确实需要走交互式登录时，在工具箱界面里按提示重新登录
> （程序会在日志窗格给出指引，不会崩溃）。

## 3. 程序下载 / clawfetch 直链下载器（模块 3）

### 界面按钮
| 按钮 | 作用 |
|---|---|
| ▶ 直链下载（输入链接） | 输入 http/https 直链（或中转页链接），下载到 `downloads\direct\`，自动重试/续传/SHA-256 校验。**可一次粘多个链接**（每行一个，也可用空格分隔） |
| ▶ 直链解析（只解析不下载） | 输出真实直链、文件名、大小、是否支持续传；结果可粘到 IDM/aria2。多个链接会逐个解析后汇总显示 |
| 打开直链下载目录 | 打开 `downloads\direct\` |

### 一次下多个链接（批量）
把多个链接粘进输入框即可（多行框，能看见自己粘了几条）。提交后它们进的是
**同一个任务**，不是 N 个任务：

| 情况 | 行为 |
|---|---|
| 不同域名的链接 | 并行下载，默认同时 2 个（`-j` 可调到 1–4） |
| 同一域名的链接 | **自动顺序下载** —— 同一条源站上行被多路连接分食只会一起变慢，还容易被压出 502 |
| 文件名撞车 | 自动加编号（`xxx.bin` / `xxx (2).bin`），不会互相覆盖 |
| 中转页链接（如 `…/download/<id>`） | **先解析出真实直链，再按直链的文件名保存**（否则会存成 `<id>.bin` 这种看不懂的名字） |
| 重复粘同一条 | 自动去重，只下一次 |
| 单条链接 | 走原来的单文件路径（auto 分段自适应），行为与以前完全一致 |

任务卡片上会显示「批量下载 · N 个链接」，日志里逐条给出 `[OK]` / `[失败]` 和最终总结。
要中途放弃就点卡片上的「取消」——整批一起停，已下部分留在 `.part` 里，重跑同一条命令会续传。

> 首页那个「识别并分流」输入框也能一次粘多个：**全是直链**时会走批量；
> 如果混了快手/抖音等平台，界面会明确告诉你只处理第 1 个（混平台没法用一条命令表达），
> 不会闷声把其余链接丢掉。

### 命令行直用（进阶）
```powershell
cd "C:\Users\Mechrevo\Desktop\视频下载工具箱\modules\clawfetch"
python clawfetch.py "https://example.com/file.zip" -o "..\..\downloads\direct"
python clawfetch.py "链接1" "链接2" -j 2     # 多链接并行
python clawfetch.py "链接" --resolve --json  # 只解析
python clawfetch.py --help                    # 全部参数
```

```powershell
# 明确指定走不走代理（默认 auto = 沿用系统/环境设置）
python clawfetch.py "链接" --proxy none            # 强制直连，忽略一切代理
python clawfetch.py "链接" --proxy http://127.0.0.1:7890   # 只走这个代理
```

### 退出码速查
0 成功 | 2 参数错误 | 3 无效链接 | 4 连接失败 | 5 HTTP 错误 | 6 超时 | 7 校验失败 | 8 磁盘错误 | 130 用户中断（重跑同命令自动续传）

### 一直失败怎么办？（照着做，别靠猜）

先看每次运行开头的 `[代理] …` 那一行 —— 它写明了**这次实际走了哪条出网路径**。
"下载失败"里最难查的就是这件事：以为直连，其实绕到了某个代理端口上。

| 症状 | 先试 | 为什么 |
|---|---|---|
| 报 `连接/读取超时`、进度条不动 | **别加大超时**，改成 `-t 20 -n 100` 重跑 | 反直觉但实测过：卡住的请求要等 `-t` 秒才被放弃，每次放弃都得重新排队。**20 秒果断切断 + 立刻重来**，撞上源站"好窗口"的机会反而多得多 |
| 报一堆 `HTTP 502` / `HTTP 500` | 先直接重跑；还不行再勾「兼容弱源站」或 `-s 1` | 源站扛不住多连接。auto 现在遇到 5xx 风暴会**自动熔断、锁死为单连接**（本次运行内不再升档）。**进度会续传，不会白下** |
| 说不清是链路还是源站 | `--proxy none` 和 `--proxy <你的代理>` 各跑一次 | 两条路的差别一眼就能看出来 |
| 手机端下发的直链失败 | 重启桥接服务后重试 | 桥接会把"外壳注入的代理"摘掉，但**改完必须重启才生效** |
| 源站很慢 / 一直 502 / 是临时隧道链接 | 勾上输入框旁的「兼容弱源站（单连接）」 | 直接从单连接起跑，跳过"先开 8 个、撞 502 再往下退"那段白等 |

> 正常情况下不必手动干预：auto 模式会**自己降到单连接**（遇到并发拖后腿的源站时），
> 也会在 5xx 刷屏时熔断。那个勾选框是给"一眼就知道源站很弱"的场合省时间用的。
>
> **源站"半死不活"时也不要放弃。** 实测过一条这样的源站：响应头 0～>60 秒随机抖动，
> 前 17 次尝试磨了 20 分钟才推进 5 MB —— **但第 18 次撞上好窗口，连续 25 分钟不停给数据，
> 818.91 MB 一次下完**（`-s 1 -t 20 -n 100 --backoff 2`，总耗时 44 分 59 秒，
> SHA-256 独立复核一致）。所以这类源站的正确姿势是**短超时 + 单连接 + 大量重试 + 耐心**，
> 而不是加大超时或等它"恢复"。**已经下到的进度会保留，重跑同一条命令即可续传。**

### 关于磁盘占用（容易误判）

多线程分段下载会**先把 `.part` 文件预分配到整个文件那么大**，NTFS 上没标稀疏属性，
所以是**真占盘**：一个只下到 2 MB 的 818.91 MB 断点，在资源管理器里就是 818.91 MB。
`下载失败` 时未完成的断点会被移进同目录的 `.clawfetch_trash\`（**不删除**）。
想清理就删那个目录；但里面那份 `.part` 只有在**同名真文件还没下完**时才是"可续传的当前进度"
（真文件已经下完的话，隔离区里那份就是纯冗余，可放心删）。

完整参数/台账/FAQ 见 `modules\clawfetch\README.md`。

## 4. 直播自动录制（模块 4）

监控快手/抖音直播间，**开播后自动开始录制**，断流 15 秒自动重连，下播后自动合并成完整文件。

### 界面按钮
| 按钮 | 作用 | 何时用 |
|---|---|---|
| ▶ 直播录制器（图形窗口） | 打开录制器主界面（添加/管理监控房间、看状态与日志） | 日常使用 |
| ▶ 直播扫码登录（快手/抖音） | 弹出浏览器扫码登录，凭证写入模块配置 | **录不到指定的快手主播时** |
| 🔍 直播录制环境自检 | 无界面检查依赖/ffmpeg/配置/解析层 | 录制不工作时**先跑这个** |
| 打开录像目录 | 打开录像根目录（按 `平台\昵称\日期` 分类） | 找录好的文件 |

### 第一次用，按这个顺序
1. 点「▶ 直播录制器（图形窗口）」打开界面。
2. 点界面工具栏「添加直播间」，把链接粘进去（每行一条，快手/抖音分享链都支持）。
   - 取链接：快手 App → 进直播间 → 分享 → 复制链接（形如 `v.kuaishou.com/xxxx`）；抖音同理（`v.douyin.com/xxxx`）。
3. 点「开始监控」。程序按设定间隔（默认 60 秒）轮询开播状态，**开播即自动录制**，下播自动收尾。
4. 想稳定录到**你指定的**主播，先点主界面里的「直播扫码登录（快手/抖音）」登录一次（原因见下）。

### 录像文件在哪、长什么样
- 根目录：`downloads\live_recorder\`（即工具箱内的 `downloads\live_recorder`）
  （可在「直播录制器 → 设置 → 录制」里改；菜单的「打开录像目录」会跟着变）
- 三级分类：`平台\昵称\日期\`
- 文件名：`{平台}_{昵称}_{YYYYMMDD_HHMMSS}_{分段序号}.flv`
- 实例：`快手_传奇妮轩_20260923_190343_001.flv`
- 单场超过 4GB（可调）或到时长上限会**自动分卷**，结束后**无损合并**（`-c copy`，不重新编码）

### 命令行直用（进阶）
```powershell
cd "C:\Users\Mechrevo\Desktop\视频下载工具箱\modules\live_recorder"
..\..\runtime\live-recorder-env\Scripts\python.exe main.py              # 启动界面
..\..\runtime\live-recorder-env\Scripts\python.exe main.py --selftest   # 环境自检
..\..\runtime\live-recorder-env\Scripts\python.exe main.py --version    # 版本号
..\..\runtime\live-recorder-env\Scripts\python.exe login.py kuaishou    # 只登录快手
```
也可双击模块内的 `start.bat` / `login.bat` / `selftest.bat`（会自动找到工具箱的运行时）。

### 为什么快手必须登录
快手网页端对**未登录访客**关闭了「按房间查询」的接口（固定返回占位响应），
并对自动化访问以「请求过快」拦截——实测无头 Chromium、有头 Chromium、有头真实 Chrome
三者**全部**被拦截，说明这不是浏览器指纹问题，而是访客级限制。
未登录时程序只能用**推荐流索引**兜底，只能录到「恰好被推荐到」的房间
（默认拉 3 页 ≈ 30 个房间，可在「设置 → 账号」调大，最多 10 页）。
**登录一次即可监控任意指定主播。** 抖音目前无需登录。

### 常用限制与提示
| 现象 | 说明 / 处理 |
|---|---|
| 快手录到的是别人的直播 | 处于未登录状态，只能靠推荐流兜底 → 点「直播扫码登录（快手/抖音）」 |
| 提示「请求过快 / 风控」 | 快手访客级限制，登录后消失；也可在设置里把「检查并发数」调小 |
| 磁盘剩余 < 10GB | 程序自动暂停全部录制（阈值可在「设置 → 录制」改） |
| 想同时录很多房间 | 「设置 → 录制 → 同时录制数」有上限（默认 8），注意带宽与磁盘 |
| 某个房间显示「未知」而非「未开播」 | 该房间刚开播、还没进推荐流。这是刻意的保守判定，避免把「没查到」误报成「没开播」 |

完整使用说明见 `modules\live_recorder\README.md`；架构设计与排查流程见 `modules\live_recorder\ARCHITECTURE.md`。

## 5. 常见问题

## 6. 卸载 / 回滚

见《备份与回滚说明.md》。一句话：删除整个"视频下载工具箱"文件夹即完全卸载；工作区那份 `live_recorder\` 已收敛为只读代码快照，不含运行时。
⚠️ **注意：直播录像现在存放在工具箱内的 `downloads\live_recorder\`**——删工具箱会**连带删掉录像**，
需要保留的话先把 `downloads\live_recorder` 拷出来。
