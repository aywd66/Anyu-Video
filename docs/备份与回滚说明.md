## 2. 回滚场景与步骤

### 场景 A：不用合并项目了，回到原项目
1. 三个原项目从未被修改，直接继续用原入口：
   - 桌面「抖音下载器」快捷方式（`E:\录屏\dysp\dyxz\启动抖音下载器.bat`）
   - 桌面「快手一键下载」快捷方式（`E:\录屏\spxz\tools\快手一键下载器.pyw`）
2. 或恢复桌面一键脚本指向（如曾改动）：无需恢复——一键下载.bat/一键解析.bat 仍指向原 DELIVERY\clawfetch，未被合并改动。
3. 若只想删除合并项目：直接删除 `C:\Users\Mechrevo\Desktop\视频下载工具箱` 整个文件夹，无系统残留（不写注册表、不装全局包、不加开机项）。

### 场景 B：合并项目坏了，想恢复合并项目自身
1. 代码层：用备份库对应目录覆盖 `modules\` 下同名模块（注意：合并引入的改造——路径参数化、yt-dlp 调用方式、toolbox——会被旧代码覆盖，恢复后需重新做合并改造，或从备份恢复**改造前**状态后再按《功能来源对照表》§五 重放改造）。
2. 数据层：
   - 抖音数据库：`data\douyin\dy_downloader.db` ← 备份 `douyin-dyxz-data\dy_downloader.db`（注意先备份合并后新产生的记录）。
   - 快手台账：`data\kuaishou\download_log.json` ← 备份 `kuaishou-spxz\download_log.json`。
3. 登录态：`runtime\kuaishou-login-profile\` ← 备份 `kuaishou-spxz-login-profile\`（若合并项目内登录态损坏）。

### 场景 C：换机器迁移
1. 整目录拷贝"视频下载工具箱"到新机器。
2. 新机器装 Python 3.14（安装路径若不同）：改两个 venv 的 `pyvenv.cfg` 的 `home`/`executable` 两行指向新解释器（文本编辑即可，venv 可跨路径工作）。
3. 或重建 venv（按《统一依赖清单》§二/§三 逐包装）：
   - `python -m venv runtime\douyin-venv` + `pip install -r`（对照清单）
   - 快手 venv 的 yt-dlp 是源码安装，重建时用 `pip install yt-dlp==2026.08.19`
4. Edge/ffmpeg 为系统级，按需安装。

### 场景 D：只想撤销某一次代码改造
《功能来源对照表》§五 逐文件列出了合并引入的全部代码变更及原因；原文件在备份库中均有合并前副本，单文件覆盖即回滚。

## 3. 主要风险项登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 抖音登录态降权（平台侧） | 单视频详情接口被过滤，无法下载部分视频 | 重新扫码登录刷新 Cookie；备份库中有合并前 Cookie 文件可回滚 |
| 快手 Cookie 过期 | 全量下载退化为仅公开作品 | 「扫码登录」按钮内置刷新流程 |
| 平台改版（抖音 API/快手页面） | 对应模块功能失效 | 记入风险；修复属新需求需另行确认（Goal 边界） |
| venv 依赖基础解释器路径 | 换机器 venv 启动失败 | 场景 C 的 pyvenv.cfg 两行修复，或重建 venv |
| 台账删除导致重复下载 | 快手旧作品重复下载 | 台账文件不要随手删；误删后可从备份恢复 |
