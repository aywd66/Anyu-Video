## 3. 主要风险项登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 抖音登录态降权（平台侧） | 单视频详情接口被过滤，无法下载部分视频 | 重新扫码登录刷新 Cookie；备份库中有合并前 Cookie 文件可回滚 |
| 快手 Cookie 过期 | 全量下载退化为仅公开作品 | 「扫码登录」按钮内置刷新流程 |
| 平台改版（抖音 API/快手页面） | 对应模块功能失效 | 记入风险；修复属新需求需另行确认（Goal 边界） |
| venv 依赖基础解释器路径 | 换机器 venv 启动失败 | 场景 C 的 pyvenv.cfg 两行修复，或重建 venv |
| 台账删除导致重复下载 | 快手旧作品重复下载 | 台账文件不要随手删；误删后可从备份恢复 |
| **playwright 版本被随手升级** | 期望的 chromium 内核不在共享缓存里 → 「浏览器兜底取流」「扫码登录」失效，且需重新下载上百 MB | 锁 `playwright==1.63.0`；自检第 21 项实测守护 |
| **模块 4 的 config.json 被提交到仓库** | 快手 `passToken`/`userId` 等账号凭证泄露 | 已在工具箱与模块两处 `.gitignore` 中排除；备份时手动留存 |
| **直播录像占满磁盘** | 录制中断，影响其他模块 | 模块自带磁盘守护（剩余低于阈值暂停全部录制，默认 10GB）；录像目录可按日期清理 |

## 4. 备份库维护建议

- 备份库在 C 盘（约 1.3GB），如需空间可压缩归档（`dy_downloader.db` 可压缩约 70%）。
- 建议保留至合并项目稳定运行 2-4 周后再决定归档/删除。
- 每次对合并项目做较大改动前，先把当前状态复制进备份库（带日期子目录）——
  本次模块 4 并入即按此规矩建了 `merge-2026-09-23\pre-liverecorder\`。
- 备份库只留**会被改动的小文件**（代码/配置/文档/启动器）；venv、录像、下载产物等大体积可再生资源不入库。
