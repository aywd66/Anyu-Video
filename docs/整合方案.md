## 三、执行方案

### 阶段 0 · 停机（前置条件，必须由你操作）

**当前有 4 个旧版 LiveRecorder 实例在后台运行**：

| 启动时间 | venv stub pid | 真实解释器 pid |
|---|---|---|
| 13:23:08 | 71624 | 69984 |
| 14:19:00 | 53004 | 73508 |
| 18:36:57 | 76004 | 72368 |
| 19:01:55 | 78516 | 39700 |

其中 19:01 那个**正在录制** `快手/forever1421yl`，文件已 **521 MB** 且仍在增长，
由 `ffmpeg.exe`（pid 82800）持有写句柄。

**安全停机方式**：切到对应窗口 → 点右上角 **×** → 弹窗选「**是**」。

> 该程序 `ui/main_window.py:716 closeEvent()` 的实现是：
> 确认后调用 `engine.shutdown()`（停止全部录制并**无损合并**已录分片）→ 再 `store.save()` 写回配置 → 退出。
> **所以关窗口就是优雅停止。**
> ⚠️ **不要直接 kill 进程** —— 那会让 FLV 尾部索引不完整，分片无法合并。

**不必停的**：2 个抖音下载器实例（09:00:03 / 19:38:39 启动，用着 `data\douyin\dy_downloader.db`）。
A / C 档都不碰 `data\`，无需为它们停机。

### 阶段 B · 收敛 LiveRecorder（需先完成阶段 0）

目标：把「工作区副本」与「工具箱副本」合成**一份**。三个选项：

#### B1 · 归档法（最稳，推荐）
1. 删除工作区那份的 `.venv`（**346 MB**，即绑死 `.workbuddy` 工具运行时的那份）
2. 工作区那份只保留约 1 MB 代码 + 文档，在 `README.md` 顶部标注「只读快照，正式入口在工具箱」
3. 配置只保留工具箱那份，工作区那份改名为 `config.json.bak`

- ✅ 零风险，随时可回退
- ⚠️ 仍是两份代码（但体积从 347 MB 降到 ~1 MB）

#### B2 · 目录联接（真正物理合一）
1. 先删工作区 `.venv`
2. 把工作区目录改成指向工具箱模块的 junction：
   ```bat
   rmdir /s /q "C:\Users\Mechrevo\WorkBuddy\2026-09-23-06-15-14\live_recorder"
   mklink /J "C:\Users\Mechrevo\WorkBuddy\2026-09-23-06-15-14\live_recorder" ^
            "C:\Users\Mechrevo\Desktop\视频下载工具箱\modules\live_recorder"
   ```
   （`mklink /J` **不需要管理员权限**）

- ✅ 改一处两边同时生效，物理上只有一份
- ⚠️ 工作区若被清理，链接会断（真实数据在工具箱，安全）；反向删除工具箱则两个路径同时失效（有 `.openclaw-backup` 兜底）

#### B3 · 删除法
直接删除工作区那份。工具箱已有完整代码，`.openclaw-backup` 亦有归档。
- ✅ 最彻底
- ⚠️ 不可逆，且失去「工作区可继续开发」的便利

**B 档收尾（无论选哪个）**：
- 确认 `modules\live_recorder\config.json` 的忽略规则仍在 `.gitignore` 里
  （该文件含快手 `passToken` = **账号凭证**，绝不能入库。✅ 已配置）
- 复跑工具箱自检 + 模块自检（`main.py --selftest`）

### 阶段 C · 录像收进工具箱（可选，需 B 完成）

**建议做的理由**：工具箱的既有约定就是「产物放 `downloads\<模块>\`」——
`downloads\kuaishou`、`downloads\douyin`、`downloads\direct` 三个子目录已经就位，
**模块 4 是唯一的例外**（把录像扔在 `C:\Users\Mechrevo\LiveRecorder`）。

步骤：
1. 停掉录制（阶段 0）后，把 `config.json` 的 `save_path` 改为：
   ```
   C:\Users\Mechrevo\Desktop\视频下载工具箱\downloads\live_recorder
   ```
2. 把 `C:\Users\Mechrevo\LiveRecorder` 的 **1.8 GB** 移入该目录
   - **同盘移动（C: → C:）是秒级 rename，不是拷贝**，不产生额外 1.8 GB 占用
   - 但仍建议先确认磁盘余量
3. 无需改代码：菜单「打开录像目录」按钮**实时读取 config.json**，会自动跟着新路径走
4. `downloads/` 已在 `.gitignore` 中 ✅ 录像不会进 git

- ⚠️ 唯一的反对意见：录像会随直播持续增长，之后工具箱目录会越来越大。
  但 `downloads\` 本来就是「产物区」，这个增长是符合设计的位置。

**若选择不搬**：保持现状也可用，只是「一处管理」不彻底。
