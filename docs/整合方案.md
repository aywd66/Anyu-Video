#### 执行中发现的关键事实（与最初判断不同，值得记录）

最初以为「runs 被提交在 master 历史里」，实测**并非如此**：

```
refs/heads/master                           含 runs 的提交数 = 0
refs/heads/feature/ui-kit-bright-business   含 runs 的提交数 = 0
refs/tags/v1.0-bright-merged                含 runs 的提交数 = 13   ← 唯一污染源
```

那 13 个提交属于 `tag v1.0-bright-merged` 指向的**一条废弃历史线**
（`baseline: pre-integration` → `feat(ui): integrate bright-business UI kit` →
merge → Revert → Reapply → … → `feat(toolbox): add Plan-C UI launcher button`），
是 Plan-C 整合过程中被 revert 又重新应用留下的中间状态。
其全部成果**已通过 `feat(home): merge Plan-C workbench as app home` 进入 master**，
代码没有丢，只是 git 历史里躺着 1 GB 测试文件。

#### 踩到的坑：`filter-branch` 必须带 `--tag-name-filter cat`

第一次执行：
```bat
git filter-branch --force --index-filter "<rm>" -- --all
```
结果：`master` / `feature` 报告 `unchanged`（**这是正确的**，它们本就干净），
但 tag 指向的那条线的**祖先提交没有被重写** —— 因为未指定 `--tag-name-filter` 时
filter-branch 不会正确更新标签所引用的历史。

正确写法（第二次执行后所有 ref 的 runs 计数归零）：
```bat
git filter-branch --force --index-filter ^
  "git rm -r --cached --ignore-unmatch modules/clawfetch/tests/runs" ^
  --tag-name-filter cat -- --all
```

另外：`git gc --aggressive` **不足以**瘦身——只能压紧仍可达的对象。
必须先让目标对象**不可达**（重写历史 + 删除 `refs/original` + `reflog expire`），
再 `git gc --prune=now` 才能真正回收。仅打包（不重写历史）只能把 253 MB 压到 124 MB。

### 停机过程（实际怎么做的，以及为什么"点了 × 却没关掉"）

**第一步发现窗口其实没关**：用户点 ×（"退出确认"后）窗口仍在 —— 枚举窗口可见 4 个
`Qt6112QWindowIcon` 主窗口，进程 69984/73508/72368/39700 全在，日志仍在轮询、
录像文件 4 秒涨 1 MB。原因是该确认框把 **`No` 设为默认按钮**，误按即走 `event.ignore()`。

**第二步用 Win32 消息完成优雅退出**（等于替用户点"是"）：

```
对主窗口 PostMessage(WM_CLOSE)
  → 枚举到同一 pid 下、标题为「退出确认」的窗口（类名 Qt6112QWindowIcon）
  → 向该窗口发送 Alt+Y（WM_SYSKEYDOWN / WM_SYSKEYUP）
  → closeEvent 继续走 engine.shutdown() → 无损合并 → store.save() → 退出
```

> 关键：这个确认框是 **Qt 自绘对话框**（类名 `Qt6112QWindowIcon`），**不是** 原生 `#32770`，
> 子按钮不是 native window，`BM_CLICK` 点不到 —— 只有加速键这条路径可行。
