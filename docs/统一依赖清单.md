## 四、live-recorder-env 清单（runtime\live-recorder-env，Python 3.14.2）

2026-09-23 并入模块 4 时，用工具箱同一套基础解释器（Python 3.14.2）新建的 venv。
版本**按模块原环境锁定**，而不是装最新——原因见下面「版本锁定理由」。

| 包 | 版本 | 用途 |
|---|---|---|
| PyQt6 | 6.11.0 | 图形界面（主窗口/设置/扫码登录对话框） |

| playwright | 1.63.0 | 浏览器兜底取流 + 扫码登录（见版本锁定理由） |

传递依赖：PyQt6-sip 13.12.0、PyQt6-Qt6 6.11.2、greenlet 3.5.6、pyee 13.0.1、
httpcore 1.0.9、h11 0.16.0、anyio 4.15.1、certifi、charset_normalizer 3.5.1、

完整冻结清单：`runtime\live-recorder-env` 内 `pip list --format=freeze`（17 个包）。

### 版本锁定理由（重要，别随手升级）

1. **playwright 锁 1.63.0**：浏览器内核来自系统共享缓存 `%LOCALAPPDATA%\ms-playwright\`，
   1.63.0 对应其中的 `chromium-1243`。升到更新版本会要求一个缓存里没有的 chromium 版本，
   需要重新下载上百 MB 浏览器；离线环境下「浏览器兜底取流」与「扫码登录」会直接失效。
   自检第 21 项会实测 `p.chromium.executable_path` 是否存在，专门守护这条。
2. **PyQt6 锁 6.11.0**：模块在原环境实测通过的版本（PyQt6 提供 `cp310-abi3` 轮子，
   天然兼容 Python 3.14，无需为 3.14 单独找包）。
3. brotli 有 C 扩展，必须是带 `cp314` 轮子的版本（1.2.0 具备）；若哪天换基础解释器，
   这一项最容易踩坑，装完请跑 `python tests\selftest.py` 复核。

## 五、系统级公共依赖（去重后全项目共享单份）

| 组件 | 位置 | 被谁使用 |
|---|---|---|
| Python 3.14.2 基础解释器 | `C:\Users\Mechrevo\AppData\Local\Programs\Python\Python314` | 三个 venv 的 pyvenv.cfg home 均指向此处 |
| ffmpeg / ffprobe | 系统 PATH | 抖音（合成/转写）、快手（校验）、**直播录制（拉流录制与分片/合并，核心依赖）** |

> 说明：venv 的 pyvenv.cfg 引用基础解释器路径。若换机器且路径不同，按《备份与回滚说明》§3 重建 venv 即可（依赖清单在本文件）。
> 直播录制模块还依赖一个外部的 **ffmpeg**（非 pip 安装），本工具箱沿用系统 PATH 里的那一份，与另两个模块共用，
> 不额外打包副本；`main.py --selftest` 第 2 项会报告实际解析到的 ffmpeg 路径与版本。

> **为什么模块 4 的 venv 是重建而不是像前两个模块那样整体复制？**
> 它的原 `.venv` 建在 `C:\Users\Mechrevo\.workbuddy\binaries\python\...`（另一个工具的托管运行时）之下，
> 整体拷进工具箱后会**长期依赖那个工具存在**——那个目录一旦被清理，工具箱就启动不了。
> 而前两个 venv 建在通用的 Python 314 目录下，复制后依然自洽。因此模块 4 按《统一依赖清单》第四节重新装了一份，
> 换来的是「工具箱整个目录拷走即可用」这条性质不被破坏。

未发现版本冲突：三个 venv 隔离运行，共享组件（ffmpeg/Edge/浏览器缓存）无版本要求冲突。
