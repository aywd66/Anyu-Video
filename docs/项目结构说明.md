## 2. 模块组织原则

1. **代码与数据分离**：`modules\` 只放代码；`data\` 放台账/数据库；`downloads\` 放下载产物。
2. **运行时与代码分离**：`runtime\` 集中放三个 venv 和登录态，模块代码不包含运行时路径
   （模块 4 的 `.bat` 按「工具箱 runtime → 模块内 `.venv` → PATH」三级回退查找解释器）。
3. **模块间零耦合**：
   - 抖音模块只读写 `modules\douyin\` 与 `data\douyin\`、`downloads\douyin\`。
   - 快手脚本通过 `_find_root()` 自动定位项目根（向上查找含 `data\kuaishou` 的目录），默认输出到 `data\kuaishou\`，登录态固定读 `runtime\kuaishou-login-profile\`。
   - clawfetch 完全自包含，产物写 `downloads\direct\`。
   - 直播录制模块自包含在 `modules\live_recorder\`：配置写在模块自己的 `config.json`，
     录像根目录由配置项 `save_path` 决定（现为工具箱内的 `downloads\live_recorder\`，
     按 `平台\昵称\日期` 三级分类）。
     菜单里的「打开录像目录」按钮会实时读取该配置项，而不是写死路径。
   - 四个模块之间没有任何 import 依赖或共享可变状态；统一入口只做“启动器 + 日志窗格”。

> **模块 4 的录像也曾放在工具箱之外**（`C:\Users\Mechrevo\LiveRecorder`），原因是并入时那里
> 已有累计录像、且有录制任务正在写盘，不宜强拆。2026-09-23 停机整合后已整体搬入
> `downloads\live_recorder\`（同盘 rename，约 2.1 GB），至此**四个模块的产物位置完全统一**。
> ⚠️ 副作用：录像不再"在工具箱之外"，**删工具箱会连带删掉录像**。

## 3. 公共依赖去重说明

| 公共资源 | 去重处理 |
|---|---|
| ffmpeg / ffprobe | 四个模块都用到，统一用系统 PATH 中的 ffmpeg（单一份，各模块不再自带副本） |
| Edge 浏览器 | 快手（playwright channel="msedge"）与抖音（浏览器兜底）共用系统 Edge，不打包浏览器二进制 |
| playwright 浏览器缓存 | 系统 `ms-playwright` 缓存目录一份；三个 venv 的 playwright（1.62 / 1.63）共享同一浏览器缓存 |
| Python 3.14 基础运行时 | 三个 venv 共用同一个基础解释器 `C:\Users\Mechrevo\AppData\Local\Programs\Python\Python314`（venv 只增量装包） |

> 三个 venv 未强行合并成一个：抖音依赖 aiohttp/httpx/rich 全家桶，快手依赖 yt-dlp 源码级安装 + playwright 1.63，
> 直播录制依赖 PyQt6（GUI 框架，与另两个模块毫无交集）。
> 强行合并需要重新解析全部依赖并回归测试全部功能，风险远大于收益。保留三个隔离 venv 就是"统一去重"的落地形态——
> 公共资源（ffmpeg/Edge/playwright 浏览器缓存/基础解释器）真正只有一份。
>
> **playwright 版本为什么锁 1.63.0？** 浏览器内核是共享缓存，版本必须与缓存里的
> `chromium-1243` 对应（见 `runtime\live-recorder-env` 的 playwright `browsers.json`）。
> 随手升到更新版本会要求一个不存在于缓存中的 chromium 版本，从而需要重新下载上百 MB 浏览器、
> 并且让「浏览器兜底取流」在没网时直接失效。自检第 21 项会实测这条链路。

## 4. 重名冲突解决记录

合并过程中出现两类潜在冲突，处理如下：

1. **脚本同名默认路径**：快手脚本原默认输出 `E:\录屏\spxz`，与抖音 `./Downloaded/` 语义冲突。
   解决：全部参数化——快手脚本统一默认 `data\kuaishou\`（通过 `_find_root()` 自动定位），抖音 `config.yml` 的 `path`/`database_path` 改为指向 `downloads\douyin\` / `data\douyin\`（相对 `modules\douyin\` 解析为项目内路径）。
2. **`download_log.json` 台账归属**：快手脚本之间原已约定“统一写主台账”，合并后主台账唯一存放于 `data\kuaishou\download_log.json`，脚本内 `LOG_PATH`/`OUTDIR` 已指向该处，无第二份台账。

并入模块 4 时新增一类冲突，处理如下：

3. **包名与父目录的关系**：`live_recorder` 内部用的是 `from live_recorder.xxx import ...`
   这种绝对导入，而 `main.py` 会把「自己的上一级目录」插进 `sys.path`。
   因此**模块目录必须叫 `modules\live_recorder\`、不能改名**（曾考虑叫 `liverecorder` 以统一英文缩写，
   但那会让 `import live_recorder` 直接失败）。目录名即包名，是硬约束。

变量/类名层面无冲突：四个模块运行在各自解释器进程中，Python 模块命名空间天然隔离。

## 5. 开箱即用要点

- 双击 `启动工具箱.vbs`：由 wscript 以「隐藏窗口」方式拉起 `runtime\douyin-venv\Scripts\pythonw.exe` 启动统一菜单，
  **不创建任何控制台**；venv 缺失时依次回落快手/直播运行时，最后回落系统 PATH 的 `pythonw`。
- `启动工具箱.bat` 是同一件事的备用入口：改用 `start "" pythonw.exe` 后立刻退出，
  cmd 窗口只闪一下（`.bat` 由 cmd.exe 执行，这不可避免）。它真正的价值是排错——
  正式启动前先用 `pythonw -c py_compile` 预检 `toolbox.py`，编译不过就回落到控制台模式把 traceback 打出来。
- 不需要 `pip install` 任何东西——三个 venv 的包齐全（自检 130 项含逐包 import 验证）。
- 快手模块的登录态已迁移并验证有效（2026-09-21 实测 Cookie 注入 11 项、真实下载 1/1 成功）。
- 抖音模块 Cookie 文件已随代码迁移；登录态过期时在菜单里点「抖音下载器」按提示重新登录。
- 快手模块需要 Edge 浏览器（系统已装）；抖音 WebUI 启动后浏览器自动打开 127.0.0.1:8518。
- 直播录制模块的运行时依赖已装齐（PyQt6 6.11.0 / httpx 0.28.1 / requests 2.34.2 / brotli 1.2.0 / playwright 1.63.0），
  浏览器内核复用系统 `ms-playwright` 缓存，**无需额外下载**。
- 直播录制要能监控**指定的**快手主播，需先在菜单里点「直播扫码登录（快手/抖音）」登录一次
  （快手对未登录访客关闭了「按房间查询」接口，未登录时只能录到推荐流覆盖的房间）。

## 6. 维护指引

- 换机器迁移：整个“视频下载工具箱”目录拷走即可；前提是新机器也装了 Python 3.14 基础解释器（或改用其他 3.10+ 解释器重建 venv，见《备份与回滚说明》）。
- 新增作品清单：直接放进 `data\kuaishou\`，`--list` 参数引用即可。
- 增删模块：在 `modules\` 增删目录，并在 `toolbox.py` 的按钮区加对应启动项；模块间无耦合，增删不影响其他模块。
  菜单左栏按两列网格排布（见 `toolbox.py` 里的 `block()` 助手，左列 `col_a` / 右列 `col_b`），
  模块再多也能一屏放下；外层还套了一层可滚动画布作为兜底，滚动条会按需自动显隐。
- 改动菜单按钮后请跑一次 `python tests\selftest.py`：最后几项会检查模块 4 的启动脚本是否齐全，
  以及 `toolbox.py` 是否还包含 `lr_gui`/`lr_login`/`lr_selftest`/`lr_open_dir` 四个入口
  （防止「功能还在但按钮被误删」这种静默失效）。
