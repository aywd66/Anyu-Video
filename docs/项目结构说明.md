## 2. 模块组织原则

1. **代码与数据分离**：`modules\` 只放代码；`data\` 放台账/数据库；`downloads\` 放下载产物。
2. **运行时与代码分离**：`runtime\` 集中放两个 venv 和登录态，模块代码不包含运行时路径。
3. **模块间零耦合**：
   - 抖音模块只读写 `modules\douyin\` 与 `data\douyin\`、`downloads\douyin\`。
   - 快手脚本通过 `_find_root()` 自动定位项目根（向上查找含 `data\kuaishou` 的目录），默认输出到 `data\kuaishou\`，登录态固定读 `runtime\kuaishou-login-profile\`。
   - clawfetch 完全自包含，产物写 `downloads\direct\`。
   - 三个模块之间没有任何 import 依赖或共享可变状态；统一入口只做“启动器 + 日志窗格”。

## 3. 公共依赖去重说明

| 公共资源 | 去重处理 |
|---|---|
| ffmpeg / ffprobe | 三个模块都用到，统一用系统 PATH 中的 9.0 full build（单一份，各模块不再自带副本） |
| Edge 浏览器 | 快手（playwright channel="msedge"）与抖音（浏览器兜底）共用系统 Edge，不打包浏览器二进制 |
| playwright 浏览器缓存 | 系统 `ms-playwright` 缓存目录一份，两个 venv 的 playwright 版本(1.62/1.63)共享同一浏览器缓存 |
| Python 3.14 基础运行时 | 两个 venv 共用同一个基础解释器 `C:\Users\Mechrevo\AppData\Local\Programs\Python\Python314`（venv 只增量装包） |

> 两个 venv 未强行合并成一个：抖音依赖 aiohttp/httpx/rich 全家桶，快手依赖 yt-dlp 源码级安装 + playwright 1.63，
> 强行合并需要重新解析全部依赖并回归测试全部功能，风险远大于收益。保留两个隔离 venv 就是"统一去重"的落地形态——
> 公共资源（ffmpeg/Edge/playwright 浏览器缓存/基础解释器）真正只有一份。

## 4. 重名冲突解决记录

合并过程中出现两类潜在冲突，处理如下：

1. **脚本同名默认路径**：快手脚本原默认输出 `E:\录屏\spxz`，与抖音 `./Downloaded/` 语义冲突。
   解决：全部参数化——快手脚本统一默认 `data\kuaishou\`（通过 `_find_root()` 自动定位），抖音 `config.yml` 的 `path`/`database_path` 改为指向 `downloads\douyin\` / `data\douyin\`（相对 `modules\douyin\` 解析为项目内路径）。
2. **`download_log.json` 台账归属**：快手脚本之间原已约定“统一写主台账”，合并后主台账唯一存放于 `data\kuaishou\download_log.json`，脚本内 `LOG_PATH`/`OUTDIR` 已指向该处，无第二份台账。

变量/类名层面无冲突：三个模块运行在各自解释器进程中，Python 模块命名空间天然隔离。

## 5. 开箱即用要点

- 双击 `启动工具箱.bat`：自动选用 `runtime\douyin-venv\Scripts\python.exe`（带 tkinter 8.6）启动统一菜单；venv 缺失时回落系统 PATH 的 python。
- 不需要 `pip install` 任何东西——两个 venv 的包齐全（自检 17 项含逐包 import 验证）。
- 快手模块的登录态已迁移并验证有效（2026-09-21 实测 Cookie 注入 11 项、真实下载 1/1 成功）。
- 抖音模块 Cookie 文件已随代码迁移；登录态过期时在菜单里点“抖音下载器（命令行）”按提示重新登录。
- 快手模块需要 Edge 浏览器（系统已装）；抖音 WebUI 启动后浏览器自动打开 127.0.0.1:8518。

## 6. 维护指引

- 换机器迁移：整个“视频下载工具箱”目录拷走即可；前提是新机器也装了 Python 3.14 基础解释器（或改用其他 3.9+ 解释器重建 venv，见《备份与回滚说明》）。
- 新增作品清单：直接放进 `data\kuaishou\`，`--list` 参数引用即可。
- 增删模块：在 `modules\` 增删目录，并在 `toolbox.py` 的按钮区加对应启动项；模块间无耦合，增删不影响其他模块。
