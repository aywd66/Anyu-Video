### E3. 原 venv 未复用的原因（记录决策）

模块 4 原 `.venv`（346MB）建在 `C:\Users\Mechrevo\.workbuddy\binaries\python\versions\3.13.12` 之下
（另一个工具的**托管运行时**），而前三个模块的 venv 建在通用的 `Python314` 目录下。
整体拷进工具箱后，模块 4 会长期依赖那个工具存在——它一旦被清理，工具箱就启动不了，
「整个目录拷走即可用」这条性质会被破坏。因此改为用工具箱同一基础解释器重建，
代价是一次性的装包时间，换来的是全工具箱运行时来源一致。

> 副作用：模块 4 模块名保持不变（`modules\live_recorder\`，目录名即包名，绝对导入依赖它），
> 另有 `main.py` 会把上一级目录插入 `sys.path`，所以 `modules\` 必须作为它的父目录——两条约束都已满足。

## H. 遗留风险（不影响"开箱即用"，如实记录）

1. **抖音单视频下载当前受平台风控**（登录态降权，`filter_reason=core_dep`）：与合并无关（原项目同环境同样失败，已 A/B 实测）。用户重新扫码登录后预期恢复；若平台改版需另行修复。
2. 快手登录态 Cookie 有有效期，过期后点「扫码登录」按钮刷新（已内置流程）。
3. 热榜/搜索等只读接口未登录也能用；搜索接口当前返回 0 条（未登录态平台限制）。
4. **直播录制：不登录快手只能录推荐流覆盖的房间**。快手对未登录访客关闭了按房间查询的接口，
   且对自动化访问以「请求过快」拦截（无头/有头 Chromium、有头真实 Chrome 三种实测全被拦，非指纹问题）。
   登录后可监控任意指定主播；未登录可用「推荐流页数」调大提高命中率（最多 10 页 ≈ 100 房间）。
5. ~~**直播录制：录像目录在工具箱之外**~~ —— **已解决**（2026-09-23 晚，见 I 段）：
   停机后已把 2.1 GB 录像整体迁入 `downloads\live_recorder\`，四个模块产物位置完全统一。
   代价是**删工具箱会连带删掉录像**（已写进《使用说明》§6 与《备份与回滚说明》）。
6. **python tests\selftest.py 依赖 live-recorder-env 已装好**。若该 venv 被删，自检第 18~21 项会失败——
   这是有意的：宁可自检报红，也不要让用户以为"菜单能点就没事"。

## J. 无窗口化改造（2026-09-23 20:42–21:10）

起因：双击启动工具箱后，桌面上一直挂着一个黑色终端窗口。

### J1. 定位：黑窗口到底是谁

| 发现 | 证据 | 结论 |
|---|---|---|
| `启动工具箱.bat` 用 `"%PY%" toolbox.py` **前台**运行 | 读 bat 源码 | cmd 窗口会一直挂到工具箱关闭 —— **这是用户看到的主因** |
| `_run_script` **同时**用了 `stdout=PIPE` 与 `CREATE_NEW_CONSOLE` | `toolbox.py` 原第 410–412 行 | 输出本来就已经进日志窗格，再建控制台纯属多余：菜单里每点一次按钮就多一个**空白**黑窗口；更糟的是那个窗口被误关时会连带杀掉子进程（`CTRL_CLOSE_EVENT`） |
| 两个 GUI 启动点虽用 pythonw，但解释器有降级路径 | `ks_gui` / `lr_gui` 里 `pyw if exists else _py` | pythonw 缺失时会回落到 `python.exe`，那就又弹控制台；补 `creationflags` 兜住 |

### J3. ⚠️ 一个差点造成功能损坏的误判（最值得记录的一条）

**我最初的结论错了。** 在改 `CREATE_NO_WINDOW` 之前，我用
`grep -E "input\( *['\"]|input\(\)"` 检查各模块是否读 stdin，全部返回 0 处，
于是判定「隐藏控制台是安全的」。

实际 `modules\douyin\launcher.py` **确实调用了 `input()`**，只是写法是多行的：

```python
raw = input(
    "\n请粘贴抖音链接或分享口令后回车开始下载"
    "（可一次粘多个，直接回车退出）："
).strip()
```

`input(` 后面直接换行、没有紧跟引号，所以那个正则一条都没匹配到。
**若照原计划直接隐藏控制台，抖音下载器的链接输入会立刻 EOF，功能当场废掉。**

改用宽松模式 `input\(` 重查全部 `modules\**\*.py`，真实结果是：

| 文件 | 是否读 stdin | 说明 |
|---|---|---|
| `modules\douyin\launcher.py:48` | **是** | 唯一的交互式输入点 |
| `modules\douyin\cli\login_flow.py:32` | 隐性依赖 | `sys.stdin.isatty()` 决定能否交互式重登；`sys.stdin is None` 时抛 `AttributeError`，被 `except (AttributeError, ValueError)` 捕获 → 返回 `False`，**安全降级不崩溃** |
| 其余（WebUI / 快手扫码登录 / 直播扫码登录 / 直播自检 / clawfetch） | 否 | `clawfetch.py:97` 的 `isatty` 判的是 **stdout**（决定是否画进度条），与 stdin 无关 |

**修法**：不是给抖音下载器保留控制台（那等于问题没解决），而是利用
`launcher.py` 本来就支持 `sys.argv` 传链接这一点，把入口改成
「界面多行输入框收文本 → 压成单行 → 带参数无窗口启动」。
副作用的处理已在《使用说明》§0.5 写明（交互式重登降级为日志提示，
需要时用带终端的 `启动抖音下载器.bat`）。

> 教训：判断「某程序是否依赖终端」时，正则必须用 `input\(` 这种宽松形式，
> 并在结论写进文档前**逐个打开确认**；多行调用是标准写法，只匹配 `input("` 会漏掉一整类。
