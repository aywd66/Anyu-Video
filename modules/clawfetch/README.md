# clawfetch 使用说明

clawfetch 是一条命令的直链下载器：自动探测链接可用性、断点续传、失败自动重试、SHA-256 完整性校验、下载台账可追溯。仅依赖 Python 3.8+ 标准库，**无需安装任何第三方包**。

> 适用链接：http/https 直链（含 trycloudflare 临时隧道、File To Link Bot 类 HTML 中转页）。
> 不适用：需要登录、付费或验证码的下载场景；不开发图形界面。
>
> **当前版本 v1.4.1**：新增源半死快速失败（不再空等）、同域链接自动串行调度、失败时进度保留。

---

## 1. 快速开始（三平台各一条命令）

无第三方依赖，因此没有安装步骤——装好 Python 即可运行：

| 平台 | 运行命令 |
|---|---|
| Windows（双击启动） | 双击 `一键下载.bat`（默认下载目标链接；cmd 里传参：`一键下载.bat "新链接"`） |
| Windows（命令行） | `python clawfetch.py "https://example.com/file.zip"` |
| macOS / Linux | `sh start.sh` 或 `python3 clawfetch.py "https://example.com/file.zip"` |

一键启动器默认下载目标链接、保存到 `downloads\`、台账自动生成在 `downloads\download_ledger.jsonl`；已实测通过（自动定位 Python、中转页转直链、退出码回传）。注意：`一键下载.bat` 为 ANSI/GBK 编码（中文 Windows cmd 标准），请勿另存为 UTF-8。

**只要直链不下载**：`python clawfetch.py "链接" --resolve`（加 `--json` 输出 JSON）——输出直链、文件名、大小、是否支持续传，解析结果可直接粘到 IDM/aria2 等任何下载器。

**多链接下载**：`python clawfetch.py "链接1" "链接2" ...`（或 `--batch links.txt` 从清单文件读，每行一条）。程序按来源域名自动调度：**不同域名并行**（实测 2×20MB：顺序 24.4s vs 并行 12.3s，快约 1 倍）；**同一域名自动串行**（v1.4.1 起，避免多个文件同时挤占同一个源头互相拖慢——实测同域 2×20MB 串行 24.3s 稳定完成，且不会把源头压到半死）；`-j` 控制并行路数（默认多链接时=2，`-j 1` 全顺序）。

若 `python` 不存在，Windows 可改用 `py -3 clawfetch.py ...`。

常用示例：

```bash
# 保存到指定目录（文件名自动取响应头/URL）
python clawfetch.py "https://example.com/file.zip" -o D:\downloads

# 保存为指定文件名
python clawfetch.py "https://example.com/file.zip" -o "D:\downloads\ myfile.zip"

# 弱网环境：重试 5 次、超时 60 秒
python clawfetch.py "https://example.com/file.zip" -n 5 -t 60
```

运行后无需任何人工干预：程序自动探测 → 下载 → 校验 → 报告结果，结束时明确提示成功或失败。

## 2. 参数说明

| 参数 | 默认值 | 说明 |
|---|---|---|
| `url`（位置参数） | 必填 | 下载链接，http/https 直链；缺协议前缀时自动按 https:// 处理 |
| `-o, --output PATH` | 当前目录 | 保存路径：已存在的目录、不带扩展名的新路径（自动建目录、文件名自动确定）、或完整文件路径 |
| `-n, --retries N` | 3 | 失败自动重试次数（总尝试 = N+1 次） |
| `-t, --timeout SEC` | 30 | 连接/读取超时秒数；超过即判定无响应并自动重试 |
| `--backoff SEC` | 2.0 | 重试退避基数，按 2^n 指数增长（封顶 60 秒）+ 随机抖动 |
| `-s, --segments N\|auto` | auto | 多线程分段数：auto=自适应 8→16→32（默认，聚合吞吐不涨或遇串行源自动停/回退）；N=固定段数（1=单线程） |
| `--no-resume` | 关闭 | 禁用断点续传（默认启用） |
| `--overwrite` | 关闭 | 允许覆盖同名文件（默认不覆盖，自动另存"名字 (1).ext"编号副本） |
| `--keep-part` | 关闭 | 失败后保留 .part 断点文件（默认隔离到 `.clawfetch_trash/`） |
| `--ledger PATH` | 保存目录下 `download_ledger.jsonl` | 自定义台账文件路径 |
| `--batch FILE` | — | 从文本文件读取链接清单（每行一个，# 开头为注释） |
| `-j, --jobs N\|auto` | auto | 多链接模式：1=顺序逐个（最稳）；N≥2=同时下载 N 个；auto=2（实测并行更快） |
| `--resolve` | 关闭 | 只把链接解析成直链并显示文件名/大小/续传支持，不下载；配合 `--json` 可输出 JSON 供脚本使用 |
| `-q, --quiet` | 关闭 | 静默模式：不输出进度，仅输出结果与错误 |
| `-V, --version` | — | 查看版本 |

## 3. 退出码

| 退出码 | 含义 | 典型场景 |
|---|---|---|
| 0 | 成功 | 文件已完整下载并通过校验 |
| 2 | 参数错误 | 缺少链接、参数格式不对 |
| 3 | 无效链接 | 不是合法 http(s) URL |
| 4 | 连接失败 | 域名无法解析 / 连接被拒（临时隧道可能已失效） |
| 5 | HTTP 错误 | 404/403/5xx 等，提示语区分具体原因 |
| 6 | 超时 | 服务器无响应，重试耗尽 |
| 7 | 完整性校验失败 | 本地大小与服务器报告不一致 |
| 8 | 本地 IO 错误 | 磁盘空间不足、路径无权限 |
| 130 | 用户中断 | Ctrl+C；进度保留，重跑同一命令可续传 |

## 4. 下载台账（download_ledger.jsonl）

每次下载尝试（**含失败与中断**）都追加一行 JSON 记录，可事后核查：

| 字段 | 说明 |
|---|---|
| `ts` | 记录时间（ISO 8601，含时区） |
| `run_id` | 本次运行编号（同一次运行的多次尝试共享） |
| `attempt` | 第几次尝试（0 = 下载前探测阶段失败） |
| `url` | 下载地址 |
| `status` | success / failed / interrupted |
| `http_status` | 服务器响应码（如 200/206/404） |
| `server_size` | 服务器报告的文件大小（字节；未知为 null） |
| `file_path` | 保存的绝对路径 |
| `file_size` | 该次尝试结束时的本地字节数 |
| `sha256` | 成功时的完整文件 SHA-256 |
| `resumed_from` | 断点续传起点（字节；未续传为 null） |
| `duration_s` | 该次尝试耗时（秒） |
| `error` / `hint` | 失败原因 / 处理建议 |
| `note` | 补充说明（如"进度已保留在 xxx.part"） |

示例（一行）：

> 注：台账为 UTF-8 编码；Windows PowerShell 5.1 下查看请用 `Get-Content .\\download_ledger.jsonl -Encoding UTF8`（旧版 PS 默认按 ANSI 读会显示乱码，记事本/VSCode 打开则正常）。

```json
{"schema": "clawfetch-ledger/1", "ts": "2026-08-29T18:40:00+08:00", "run_id": "1a2b3c4d5e6f", "attempt": 2, "url": "https://…", "status": "success", "http_status": 206, "server_size": 400198164, "file_path": "D:\\downloads\\file.mp4", "file_size": 400198164, "sha256": "…", "resumed_from": 123456789, "duration_s": 42.5, "error": null, "hint": null, "note": null}
```

## 5. 断点续传与失败处理规则

- 下载先写入 `<文件名>.part` 临时文件；**成功并通过校验后**才改名为正式文件，不会出现"半截文件冒充成品"。
- **续传带同文件校验**：断点与 .part.meta（URL+ETag+Last-Modified 绑定）交叉核对，服务器返回的续传起点不符或文件已被更换时，自动隔离旧进度重新下载——绝不拼接出"大小正确但内容错位"的文件。
- **多线程分段（大文件）**：≥16MB 且服务器支持 Range 时自动切多线程并发拉取（默认 8 线程，`--segments` 可调），实测限速环境提速 7.6 倍；检测到服务器串行响应（30 秒内部分分段零进度）或不支持分段时自动回退单线程。
- **多线程分段（大文件）**：≥16MB 且服务器支持 Range 时自动切多线程并发拉取，默认自适应扩线程（8→16→32，聚合吞吐提升 ≥15% 才继续扩），实测限速环境对比单线程提速 12 倍；检测到服务器串行响应或不支持分段时自动回退单线程。
- **用户中断（Ctrl+C）**：.part 保留，重跑同一命令自动从断点续传（退出码 130，有明确提示）。
- **最终失败（重试耗尽/校验不通过/404 等）**：.part 自动隔离到 `.clawfetch_trash/` 目录并记录进台账，不留脏文件；隔离文件可手工检查后删除。
- **绝不覆盖已存在的完好文件**：同名时自动另存编号副本；确需覆盖请显式加 `--overwrite`。
- 服务器不支持 Range 时自动降级为整文件重下，并在输出中说明。
- 大小校验：下载完成先比对本地字节数与服务器报告值，再计算整个文件的 SHA-256 写入台账。

## 6. HTML 中转页自动转直链

部分分享服务（如 Telegram 的 File To Link Bot）给出的 `/download/…` 链接实际是带倒计时的 HTML 页面，真实文件在同域 `/stream/…` 端点。clawfetch 在预检阶段发现响应是网页而非文件时，会自动解析页面并尝试同域 `/stream/` 端点，无需手动换链接。

## 7. trycloudflare 临时隧道：时效风险与应对

trycloudflare 链接是**临时隧道**，分享者关闭或超时后立即失效，程序无法挽回。应对步骤：

1. 拿到链接后**尽快下载**（程序会先探测，隧道存活才开跑）。
2. 探测失败时程序会明确提示"隧道可能已失效，请向分享者索取新链接"，并以非零退出码结束、台账留痕。
3. 大文件下载中断后不必重头再来：隧道仍在时重跑同一命令即断点续传；隧道已失效则等新链接后用 `-o` 指定同一目录继续。

## 8. 常见问题排查

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 无法解析域名（退出码 4） | 临时隧道已失效/过期 | 向分享者索取新链接 |
| HTTP 404（退出码 5） | 文件被删除或 token 过期 | 索取新链接；确认 token 完整 |
| HTTP 403（退出码 5） | 链接需要权限/被风控 | 确认链接是否公开；换网络环境 |
| 反复超时（退出码 6） | 网络差或服务器慢 | 加大 `-t 60`、加多 `-n 5` |
| 长时间零进度后失败（退出码 6） | 源服务器/隧道半死：能连接但不发数据 | v1.4.1 起自动快速识别：连续两轮尝试无任何新字节即停止重试（不再空等半小时），提示“源服务器半死”；已下载进度保留，稍后重跑同一条命令即可续传 |
| 大小校验失败（退出码 7） | 服务器文件中途被更换 | 重跑将重新完整下载 |
| 磁盘空间不足（退出码 8） | 目标盘满 | 清理空间后重跑 |
| 中文文件名乱码 | 终端编码差异 | 程序已做 UTF-8 兼容与 Windows 保留名处理；必要时用 `-o` 指定文件名 |
| 公司网络连不上 | 代理拦截 | 程序遵循系统环境变量 HTTP_PROXY/HTTPS_PROXY |

## 9. 异常场景自测（tests/mock_server.py）

本地模拟服务器可复现真实隧道上的各种异常，用于验收自测：

```bash
# 正常下载（5 MB 确定性文件，启动时打印 SHA-256 基准）
python tests/mock_server.py --port 8394
python clawfetch.py "http://127.0.0.1:8394/stream/83942d892579074f" -o tests/tmp

# 断流一次 → 验证自动续传后一次下完
python tests/mock_server.py --cut-at 1048576 --cut-once

# 服务器挂起 → 验证超时重试与失败隔离
python tests/mock_server.py --stall-after 65536

# 黑洞模式（源半死：连接后零字节）→ 验证快速失败与进度保留（v1.4.1）
python tests/mock_server.py --port 8394 --blackhole

# 404 → 验证失败提示、退出码与台账留痕
python tests/mock_server.py --status 404
```

预期结果：正常/断流场景最终 SHA-256 与启动打印一致；挂起/404 场景以非零退出码结束、错误提示人可读、台账有失败记录、无 .part 脏文件残留（或已隔离进 `.clawfetch_trash/`）。黑洞场景 v1.4.1 起连续两轮无进度即快速失败（实测阈值 12 秒时全程 46.9 秒），明确提示“源服务器半死、进度已保留”，.part 与 .part.meta 原样保留便于源恢复后续传。

## 10. 已知限制与风险

- 不保证临时隧道链接长期有效；失效后需要分享者提供新链接。
- 仅做大小与 SHA-256 层面的完整性核对，**不对文件内容做安全/病毒审查**。
- 不处理需要登录、付费或验证码的下载。
- 命令行程序，无图形界面。
- 极少数服务器对 HEAD/Range 行为异常时，程序以实际响应为准自动降级处理。
- 对串行响应的源（如 File To Link Bot 类单线程源）多线程无益——程序会自动检测并回退单线程，速度上限取决于源本身与临时隧道质量。
- `CLAWFETCH_STALL_ABORT` 环境变量（默认 120 秒）：单次尝试内超过该时长没有任何新数据，自动中止本轮并快速进入重试/失败判定——网络极差环境可调小（如 45），高延迟环境可调大；源半死时连续两轮无进度即快速失败。
- 超时语义为"单次连接/读取超时"而非总时长：慢速但持续吐数据的服务器不会触发总超时。
- 不支持 Cookie/登录态；链接含 `user:pass@` 凭据时可用（凭据在台账与控制台输出中自动脱敏）。
- `.clawfetch_trash/` 会随使用累积（含成功收尾后的 .part.meta 元数据），需人工定期清理或整目录删除。

## 11. 回滚与清理方法

程序只在保存目录产生四类文件，删除即完全回滚，不改系统任何配置：

- `下载的正式文件`
- `*.part`（未完成断点；成功后不存在）
- `.clawfetch_trash/`（失败隔离区，可整目录删除）
- `download_ledger.jsonl`（台账，append-only，按需归档或删除）
