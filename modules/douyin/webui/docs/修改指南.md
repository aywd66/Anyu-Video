# 后期修改指南

> 写给后续维护者（包括换了个电脑的你）。所有改动都遵循一个原则：
> **先找到配置，再动手**。90% 的修改不需要碰业务逻辑代码。

---

## 0. 改动前的准备

```bash
# 1. 进入项目目录
cd douyin-downloader-ui

# 2. 确认工作区干净（改动前先提交一次，方便随时回退）
git status
git add -A && git commit -m "改动前基线"
```

改完任何文件后刷新浏览器即可看到效果（无构建步骤）；
如果改了 JS 后页面行为异常，按 Ctrl+F5 强制刷新缓存。

---

## 1. 换文案（按钮、标题、提示语）

**去 `assets/js/config.js` 搜中文直接改。**

| 想改什么 | 位置 |
|---|---|
| 侧边栏菜单名 | `NAV.menu` 里的 `label` |
| 平台切换按钮 | `NAV.platforms` 里的 `label` |
| 工作台大标题 | `PLATFORMS.douyin.titleA / titleB` |
| 输入框占位符 | `PLATFORMS.<平台>.placeholder` |
| 下载模式名称 | `MODES` 里的 `label` |
| 画质选项 | `QUALITY` |
| 空状态文案 | `EMPTY` |
| 空状态/按钮等通用文字 | `TEXT` |

示例 —— 把「下载」按钮改成「开始下载」：

```js
// config.js → TEXT
download: '开始下载',
```

示例 —— 抖音工作台大标题换个说法：

```js
// config.js → PLATFORMS.douyin
titleA: '贴上链接，',
titleB: '立刻出发。',
```

## 2. 换配色 / 做浅色主题

**只动 `assets/css/tokens.css`。**

- 深色主题改 `:root` 里的变量：品牌双色是 `--pink`（选中/强调）与 `--cyan`（主按钮/链接）。
- 做浅色主题：在文件底部的 `[data-theme="light"]` 里已经给了一整套浅色变量，
  在浏览器控制台执行 `document.documentElement.dataset.theme = 'light'` 可即时预览；
  想默认浅色，把这段变量表的内容整体搬到 `:root` 里即可。

示例 —— 品牌强调色从品红换成琥珀：

```css
:root {
  --pink: #f5c84c;           /* 主强调色 */
  --pink-soft: rgba(245, 200, 76, 0.14);
}
```

改完检查点：工作台大标题尾句、面包屑、选中态导航点会一起变色（它们都引用 `--acc` / `--pink`）。

## 3. 换字体

`tokens.css` 里的两个栈：

```css
--font-sans: "MiSans", "HarmonyOS Sans SC", "PingFang SC", "Microsoft YaHei", …;
--font-mono: "JetBrains Mono", "Cascadia Code", …;
```

把本机已安装的字体名放到栈首位即可（本项目刻意不引远程字体，保证断网可用）。

## 4. 换图标 / 加图标

图标集中在 `assets/js/icons.js`，键名 → SVG 字符串。全站不使用 emoji 做界面图形。

```js
// 新增一个图标（24×24 视窗，stroke 线性风格）：
star4: '<path d="M12 3v18"/><path d="M3 12h18"/>',
```

用的时候 `DYIcons.icon('star4', 16)`。想整体换一套图标：只替换这个文件里的 `P` 对象即可，
页面代码里的键名不变就不用动其它文件。

## 5. 加页面

三步，全程不用碰 router 与 app：

1. 新建 `assets/js/pages/report.js`：

```js
(function () {
  'use strict';
  window.DYRouter.register('report', function (view) {
    view.className = 'content';
    view.innerHTML =
      '<div class="page-head page-head--compact"><h1 class="page-title">周报</h1></div>' +
      '<section class="card">内容…</section>';
  });
})();
```

2. `index.html` 末尾加一行：`<script src="assets/js/pages/report.js"></script>`
3. `config.js` 的 `NAV.menu` 加一项：`{ id: 'report', label: '周报', icon: 'file', group: '任务' }`

## 6. 换数据 / 对接真实后端

- **换演示数据**：直接改 `assets/js/mock-data.js`（字段说明见文件内注释）；
  改完后在设置页执行一次「重置演示数据」（它会把新数据灌入 localStorage）。
- **接后端下载**：`assets/js/api.js` 顶部 `mode: 'mock'` 改为 `'rest'`，
  后端启动方式见 README 第 5 节。页面代码零改动。
- **作者库/作品档案走后端**：在 `api.js` 里新增方法（如 `listCreators()`），
  mock 分支读 `DYStore.state`，rest 分支 `fetch` 后端接口；页面把直读 `DYStore.state.creators`
  的地方换成 `await DYApi.listCreators()` 即可。

## 7. 常见样式调整速查

| 想改什么 | 文件 / 位置 |
|---|---|
| 内容区宽度 | `tokens.css` → `--content-max` |
| 侧边栏宽度 | `tokens.css` → `--sidebar-w` |
| 卡片圆角 | `tokens.css` → `--r-card` |
| 大标题字号 | `tokens.css` → `--fs-display` |
| 间距节奏（8pt 网格） | `tokens.css` → `--sp-*` |
| 组件内边距/描边 | `components.css` 对应组件块 |

## 8. 版本管理与回滚（git）

```bash
# 看历史版本
git log --oneline

# 回滚单个文件到某个版本
git checkout <commit-hash> -- assets/css/tokens.css

# 整体回滚到交付版本 v1.0
git checkout v1.0

# 只想看看某个版本长什么样（不影响当前分支）
git checkout v1.0 -- .   # 慎用，会覆盖当前全部文件
```

约定：**每完成一个可感知的修改就 commit 一次**，提交信息写清改了什么
（例：`改文案：抖音工作台大标题`）。改坏了随时 `git checkout <hash> -- <文件>` 找回。

## 9. 修改后的自检（30 秒）

1. 刷新页面，按 F12 看控制台：无红色报错
2. 逐页点一遍侧边栏：9 个页面都能渲染
3. 改过配置类文件时：在设置页点一次「重置演示数据」，确认数据层正常
4. 改过样式时：把窗口拉窄到 375px 宽，确认没有横向滚动条
